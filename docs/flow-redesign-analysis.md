## 1. โฟลว์ปัจจุบันตามโค้ดจริง

**การจอง** (`server.js` ~9069, `BOOKING_TRANSITIONS`)

```
pending → reviewing → rejected/cancelled
pending → (POST /approve-and-assign) → approved → completed (quick-invite สร้างสัญญา)
rejected → reviewing (เปิดใหม่ได้) · cancelled = จุดจบ
```

**สัญญา**: คำเชิญ (`services/contractInvitation.js`) `pending → submitted → approved/rejected/revoked/expired` · ตัวสัญญา `active → ended/expired` (`db/migrate.js:862`)

**บิล/ชำระ**: บิล `pending → paid/overdue/void` (unique index กันบิลซ้ำต่อห้อง+งวด) · ชำระ `pending → verified/rejected` (กันสลิปซ้ำด้วย slip_hash + transaction_ref) · scheduler ในโปรเซสออกบิลรายเดือน + คิด late fee

**จุดแข็งที่มีแล้ว**: state machine จอง, lock ตอน approve, unique index กันบิล/สลิปซ้ำ, auto-verify สลิป, checkout แบบ atomic ใน `routes/tenant-ops.js`

## 3. โฟลว์ใหม่ที่เสนอ

หลักคิด: **ทุกการเปลี่ยนสถานะสำคัญ = ปุ่มเดียว ทำครบใน transaction เดียว** และ **เงินทุกก้อน (มัดจำ ค่าจอง ค่าเช่า ค่าปรับ) วิ่งผ่านระบบบิลเดียวกัน**

### 3.1 จอง → เข้าพัก → จบสัญญา

| ขั้น | ใครทำ | ระบบทำให้อัตโนมัติ |
|---|---|---|
| 1. จองออนไลน์ | ผู้เช่า | hold ห้องใน DB ทันที (TTL 48 ชม.) + กันจองซ้ำเบอร์+ห้อง + แจ้ง admin ทาง LINE |
| 2. อนุมัติ | admin กด 1 ปุ่ม | จองห้อง + ออก **บิลมัดจำ/ค่าจอง** + ส่งลิงก์สัญญา — รวม 3 ขั้นเดิมเป็นปุ่มเดียว ใน transaction เดียว |
| 3. เซ็นสัญญา + จ่ายมัดจำ | ผู้เช่า | จ่ายผ่านโฟลว์สลิปเดียวกับบิลปกติ (QR ระบุยอด + auto-verify) |
| 4. เช็คอิน | admin กด 1 ปุ่ม | contract → active, ห้อง → occupied, บันทึกมิเตอร์เริ่มต้น, ออกบิลแรกแบบ prorate |
| 5. ระหว่างพัก | — | บิลรายเดือนอัตโนมัติ (ข้อ 3.2) |
| 6. ใกล้หมดสัญญา | — | แจ้งเตือน 60/30/7 วันทั้งสองฝ่าย → admin/ผู้เช่าเลือก "ต่อสัญญา" (copy ฉบับเดิม+ราคาปัจจุบัน 1 คลิก) หรือ "แจ้งย้ายออก" |
| 7. เช็คเอาท์ | admin กด 1 ปุ่ม | มิเตอร์ปิด → บิลสุดท้าย = prorate + ค้างเก่า + late fee ค้าง **− มัดจำ** → สรุปคืน/เก็บเพิ่ม → ปิดสัญญา *ทุกฉบับ* → ห้อง vacant |

สัญญาที่ไม่ต่อและไม่แจ้งย้ายออก: เมื่อเลย end date ระบบ flip เป็น `expired` + ขึ้นรายการ "ต้องจัดการ" บน dashboard — ไม่ปล่อยเงียบ

### 3.2 บิล → ชำระเงิน

| ขั้น | รายละเอียด |
|---|---|
| 1. จดมิเตอร์ | dashboard แสดงห้องค้างจดของงวด · ห้องไหนพร้อมออกบิลได้เลย **ไม่ block ทั้งรอบ** |
| 2. ออกบิล | สร้างเป็น draft ทั้งงวด → admin review หน้าเดียว (เห็นยอดผิดปกติ 3σ) → กดยืนยันส่ง |
| 3. ส่งบิล | LINE + tenant portal + PDF + PromptPay QR ระบุยอด (มีอยู่แล้ว — คงไว้) |
| 4. ชำระ | สลิปยอด+บัญชีตรง = auto-verify ผ่านเลย · เข้าคิว admin เฉพาะเคสไม่ตรง |
| 5. ค้างชำระ | reminder อัตโนมัติ D+1 / D+3 / D+7 → late fee อัตโนมัติพร้อม audit log ทุกครั้ง |
| 6. สถานะบิล | `bill.status` คำนวณจากผลรวม payments ที่ verified จุดเดียวเสมอ (derived) — ห้ามมีโค้ดเซ็ต paid ตรง ๆ กระจายหลายที่ |

### 3.3 หลักสถาปัตยกรรมที่ต้องยึด

1. **Source of truth เดียว**: ตาราง relational เป็นหลัก · JSONB blob เหลือเป็น read-cache ที่ rebuild ได้ หรือตัดทิ้ง (ปิดข้อ 6, 7, 8, 10)
2. **Transaction + lock**: ทุก transition (อนุมัติ, เช็คอิน, เช็คเอาท์, verify สลิป) ทำใน DB transaction เดียว + `SELECT FOR UPDATE` ถือ lock จนจบ (ปิดข้อ 9, 11)
3. **Scheduler state ลง DB**: ตาราง `billing_runs(period, status, rooms_done)` — resume ได้ ไม่ออกซ้ำ (ปิดข้อ 4)
4. **เวลา/เงิน**: timezone จาก config จุดเดียว · ปัดเศษสตางค์ฟังก์ชันกลางฟังก์ชันเดียว (ปิดข้อ 17)
